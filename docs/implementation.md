# 实现与验收说明

本次实现以 `design.md`、`GLOSSARY.md` 和已有 ADR 为行为依据。首版验收目标为 Windows；Linux 提供开发、编译和进程运行测试支持。

## 配置模型

完整示例见 [config.example.json](config.example.json)。示例项目路径需要改成实际存在的目录，并自行准备运行环境及 `server.js`。

配置根对象包含：

| 字段 | 说明 |
| --- | --- |
| `version` | 当前为 `1`。不同版本拒绝加载，不猜测或自动迁移 |
| `settings.launchAtLogin` | 应用开机启动，默认关闭 |
| `tasks` | 任务定义列表，按列表顺序显示 |
| `files` | 导入文件元数据列表，由文件管理维护 |

任务字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定且唯一的身份，允许字母、数字、`-`、`_`，最长 128 字符 |
| `name` | 必填名称；不按名称或命令去重 |
| `command` | `direct` 或 `composed` 两种编辑方式之一 |
| `workingDirectory` | 工作目录，支持输入变量；需要是存在的目录 |
| `environment` | 额外环境变量的名称与文本值，值支持输入变量 |
| `variables` | 输入变量的 `value` 与 `allowEmpty`；`null` 表示未赋值 |
| `autoStart` | 每次软件启动时自动尝试一次，不自动重试 |

点击新增任务只生成界面草稿与默认路径，不创建目录或写入配置。保存时通过校验和配置冲突检查后，才创建实际使用的默认目录；保存失败会清理本次新建的空目录。放弃草稿不会留下目录，选择自定义工作目录也不会额外创建默认目录。

完整命令：

```json
{ "mode": "direct", "text": "node server.js --port ${port}" }
```

组合命令：

```json
{
  "mode": "composed",
  "parts": [
    { "kind": "program", "value": "python" },
    { "kind": "file", "file_id": "从文件管理取得的真实文件ID" },
    { "kind": "text", "value": "--name \"${name}\"" }
  ]
}
```

`parts` 首项固定为程序，其余为文本或文件引用，支持增删和排序。组成项用空格连接成一条命令；文件路径由应用引用，文本保持原样。`file_id` 是命令组成项的文件引用字段；文件元数据自身使用 `id`、`name`、`storedName`。替换文件保留 `storedName` 和实际路径。

输入变量名称区分大小写，格式为 `[A-Za-z_][A-Za-z_0-9]*`。完整命令、程序与文本组成项、工作目录及环境变量的值参与变量识别，文件引用不参与。`$${name}` 变为字面量 `${name}`。替换仅进行一遍，变量值里的 `${...}` 不再次解释，也不会自动加引号。未赋值的必填变量禁止启动；允许空值的变量可以为空。

界面保存时保留当前命令实际使用的变量。软件不读取同名系统环境变量作为输入变量赋值。任务环境变量在继承的应用环境上覆盖；Windows 按系统环境变量名称不区分大小写的规则覆盖。每次运行还带有唯一的内部进程识别标记，用于异常恢复。

## 配置写入与恢复

软件只在用户保存、导入或删除文件元数据等配置操作时写 `config.json`。运行状态和日志不写入配置文件。

写入前将磁盘内容与上次加载或保存的原始字节比较。外部内容发生变化即停止写入，由用户选择加载磁盘版本或备份后覆盖。写入采用同目录临时文件、刷新到磁盘和原子替换；上一份有效配置保存为 `config.backup.json`。

损坏或不支持的配置不会自动覆盖。用户可以恢复有效备份或新建配置；明确恢复时，损坏的原件另存为 `config.damaged-<唯一ID>.json`，有效备份保留。重新加载失败保留当前有效内存配置。全部运行实例结束后才可重新加载，重新加载不触发任务自动启动。

文件内容不存入 JSON。导入大文件通过文件复制完成，不要求一次性将全部文件读入内存。被任务定义或活跃配置快照引用的文件不能删除；引用该文件的任务运行期间不能替换。

## 命令执行与生命周期

两种编辑方式最终都生成完整命令字符串，运行前展示命令、替换后的工作目录与环境覆盖值。应用不把最终命令重新拆成程序和参数数组。

Windows 实现使用系统 `COMSPEC` 指定的命令解释器，以完整命令语义执行，通常为系统 `cmd.exe`；这属于底层机制，不增加执行终端设置。用户可以在命令中显式调用 PowerShell、Python、Node.js 或其他程序。Linux 使用 `/bin/sh -c` 执行完整命令。

Windows 通过原生 `CreateProcessW` 创建隐藏的独立控制台，利用启动属性在创建时加入专属 Job Object，初始线程恢复前完成进程管理设置。显式限制继承的句柄，避免不同任务持有彼此的输出管道。Job Object 禁止受管子进程脱离，并设置关闭最后一个管理句柄时结束整棵进程树。

停止时，独立辅助进程向该运行实例的控制台发送 `CTRL_BREAK`，并向受管图形窗口请求关闭；Linux 对进程组发送 `SIGTERM`。最多等待 5 秒，之后强制结束 Windows Job Object 或 Linux 进程组。确认树已结束才释放任务的运行资格。无法确认时保留异常状态，允许重新核查或在确认身份后清理。

开始执行前先记录本次尝试，再记录进程身份与运行状态。恢复时核查 Windows 命名 Job Object；Linux 按进程组及唯一运行标记检查遗留进程。已结束的旧活跃记录标为中断，尚存活或不能确认的记录标为异常。Linux 的补充支持使用进程组，不保证收回自行创建新会话脱离管理的程序；Windows 验收以 Job Object 管理为准。

同一任务以稳定身份检查活跃实例。不同身份的相同命令可以分别启动。运行实例保存启动时的任务与实际执行配置快照；编辑只影响下次运行。重启等待旧实例结束后读取已保存的新配置。运行中的任务不能删除。

应用本身采用单实例；再次启动显示已有窗口。关闭窗口隐藏到托盘。托盘与设置中的明确退出先停止任务，异常未处理时取消退出并提示。应用开机启动使用当前用户的登录启动机制，通过 `--autostart` 隐藏启动；手动启动显示窗口，两者都执行一次任务自动启动。

## 日志与历史

每次运行的输出按 JSONL 分开保存 `stdout` 与 `stderr`、文本和时间戳。读取管道时保留跨读取边界的 UTF-8 字符。日志是文本查看器，不提供交互输入或终端模拟。输出按 UTF-8 解码；Windows 上使用其他代码页的程序需要设置为 UTF-8 输出，例如 Python 使用 `python -X utf8` 或任务环境变量 `PYTHONIOENCODING=utf-8`。

每个任务保留最近 20 次运行，每次日志最多 10 MB；超限按完整日志片段丢弃较早内容并记录截断提示。可以复制本次全部输出、筛选输出流、清空当前运行输出，或在任务停止后清除其全部历史。损坏或不完整的单个日志片段会显示提示，其余片段仍可查看。

## 自动化验证

`pnpm test` 测试输入变量识别、转义、大小写、文件引用排除、变量配置同步、活跃状态、运行时长及不完整日志读取。

`cargo test --manifest-path src-tauri/Cargo.toml --locked --lib` 使用临时数据目录测试配置冲突与备份、失败重新加载、变量替换、文件引用保护、文件替换、日志容量、历史淘汰，以及当前平台的进程执行。Linux 额外覆盖标准输出与错误输出、环境覆盖、重复启动、配置快照、停止进程树、5 秒后强制结束、重启与异常 PID 记录恢复；Windows 测试完整命令重定向、退出码及 Job Object 停止。测试不访问用户真实 `.script-hub`。

`tests/browser-mock.js` 仅为浏览器 UI 测试提供 IPC 夹具，不进入产品入口，也不执行真实命令。浏览器检查与实际进程测试分别验证，不将模拟运行视为原生系统验收。

## Windows 人工验收

在 Windows 开发机运行 `pnpm tauri dev`，或构建后安装执行以下检查：

1. 新建完整命令任务，使用 `echo hello & echo error 1>&2`，确认输出区分两类流；检查退出码和历史。
2. 新建组合任务，导入含空格及中文名称的文件，添加文本参数并排序，核对预览及实际执行。
3. 在命令、工作目录、环境覆盖中使用输入变量；检查必填、允许空值、同名共享、大小写、`$${...}` 转义和一次替换。
4. 运行持续服务，验证连续点击启动不会产生第二个实例；复制任务后验证两个身份可独立运行。
5. 运行中编辑保存，核对旧配置快照与下次生效提示；重启后核对新配置；停止过程中禁止重复运行和删除。
6. 验证正常退出与不响应正常结束的程序，确认 5 秒后受管子进程也被结束。
7. 关闭窗口确认托盘与任务仍在；再次打开应用显示已有窗口；明确退出确认任务树结束。
8. 启用任务自动启动，重开应用检查仅尝试一次，必填变量缺失时显示原因，重新加载配置不再触发。
9. 启用应用开机启动，重新登录确认隐藏到托盘；关闭后检查登录启动项移除。
10. 手动修改 JSON，检查保存冲突选择、有效备份、无效重新加载保留当前配置、较新版本拒绝加载，以及显式恢复。
11. 验证被引用文件禁止删除、运行中禁止替换、替换后存储路径和身份不变，以及原文件移动后导入副本可用。
12. 强制结束应用后重新打开，核对旧活跃记录中断或异常；检查日志重启后可读、20 次保留和 10 MB 截断提示。

Linux 容器中的构建、领域测试与 Windows 目标类型检查不替代以上原生交互验收。
