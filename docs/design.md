# Script Hub 设计确认记录

本文记录访谈中已确认的产品边界。用户于 2026-11-16 最终确认需求无误，访谈已完成。本轮工作为需求设计与文档记录，未开始功能实现。各轮描述如有修订，以后续明确确认的内容为准。

## 第一轮：已确认

用户于 2026-11-16 接受以下全部推荐。

- 首版以 Windows 为验收目标，保留后续扩展其他系统的空间。
- 使用“任务”“运行实例”“脚本文件”区分执行配置、一次执行与文件。
- 同时支持执行后结束的一次性任务与持续运行的服务。
- 每个任务选择完整终端命令或组合编辑方式；不要求两种方式自动互相转换。
- 组合编辑方式中的组成项可增删和排序，数量不设产品上的固定上限；组成项共同构成一条命令，不表示多个执行步骤。
- 首版不做多步骤编排。
- 同一任务同时最多有一个运行实例；任务通过稳定身份区分，不按命令文本去重。复制后是独立任务，可以分别运行。
- 软件自身采用单实例；再次打开时回到已有窗口。
- 关闭窗口隐藏到系统托盘，运行中的任务继续执行。
- 通过托盘明确退出时，停止软件管理的任务及其子进程。
- 用户自行安装 Node.js、Python 等运行环境；软件允许指定程序路径，并明确展示启动失败原因。
- 首版不提供运行环境的下载、安装或版本管理。

## 第二轮：已确认

用户接受 Q7、Q9 至 Q14 的推荐，并修改 Q8 如下。

- 输入变量属于任务，自动识别并生成输入框。同一任务内同名变量共享赋值，不同任务独立赋值，不自动读取同名系统环境变量。
- 变量名区分大小写，以字母或下划线开头，后续允许字母、数字和下划线；提供字面量占位符的转义方式，具体语法待确认。
- 命令组成项只有程序、文件引用、文本三种类型；首项固定为程序，其余可增删和排序。文本完全由用户输入，可以表示一个参数或一组参数，不划分单参数与参数片段。最终拼接、引号与变量替换语义待确认。
- 文件操作称“导入”，复制到软件管理的本机目录。导入文件具有独立身份，保留原文件名供展示，同名文件不覆盖，原文件移动不影响软件中的副本。
- 首版支持导入任意普通文件，由用户选择运行程序，暂不支持文件夹或依赖项目导入。
- 每个任务可配置工作目录及额外环境变量。新增任务时仅生成草稿并展示默认的任务专属工作目录路径，用户可以更改；保存任务时才真正创建默认目录，放弃草稿不创建目录。使用自定义工作目录时不额外创建默认目录。
- 执行时继承软件环境，并应用任务环境变量覆盖值；不自动安装依赖。
- 应用设置、任务定义、变量配置和文件引用保存在一个带版本号的 JSON 中；导入文件和日志另存。
- 支持打开配置目录。手动修改 JSON 后，通过重新加载配置生效；首版不做实时监听和多端同步。
- 显示运行状态、开始时间、运行时长、结束结果；实时输出区分标准输出与错误输出，支持复制和清空。
- 首版不支持向运行程序交互输入。
- 每次软件启动，对启用自动启动的任务各尝试一次；任务独立启动，不承诺顺序，结束或失败不自动重启。
- 首版不支持任务依赖、定时执行和失败重试。
- 运行实例持有启动时的配置快照，编辑保存影响下次运行，界面提示下次生效。
- 重启先停止旧实例，确认结束后使用新配置启动；运行中的任务必须先停止才能删除。

## 第三轮：已确认

用户接受 Q15、Q17、Q18、Q20 至 Q22 的推荐，并修改 Q16、Q19 如下。

- 组合模式用空格按顺序连接组成项，生成完整终端命令；文件引用由软件处理路径引号，自由文本原样保留。
- 运行前展示替换后的命令预览；输入变量作字面文本替换，不自动将变量值包装为单个参数，用户负责必要的引号。
- 不设敏感变量类型或标记。变量统一按普通变量处理，默认记住上次赋值并保存到 JSON。
- 变量默认必填，可单独允许空值；必填变量未赋值时阻止运行，自动启动跳过该任务并展示原因。
- 被引用文件须先解除引用才能删除；可替换文件并保留文件身份和任务引用。任何引用它的任务运行时，禁止替换。
- 应用开机启动指当前用户登录 Windows 后启动软件，默认关闭；开启后登录时隐藏到托盘，手动启动显示窗口。两种启动方式均触发任务自动启动。
- 用户要求任务配置放在用户目录下，支持直接修改。具体路径与外部修改冲突规则待确认，不采用隐藏在平台专属应用数据目录内的方案。
- 保存配置时完整替换，并保留上一份有效备份；损坏时展示错误，用户选择恢复备份或新建配置，不自动覆盖损坏文件。无法识别的较新版本停止加载并提示。
- 每个任务保留最近 20 次运行记录，每次最多保留最近 10 MB 输出，超限丢弃较早输出并提示。历史记录在软件重启后可查看。
- 清空输出作用于当前查看的一次运行，另可清除任务的全部历史。
- 停止时先请求正常结束，最多等待 5 秒，再强制结束所管理的进程树；停止期间显示“正在停止”。
- 确认旧实例结束后才允许再次启动；无法确认结束时保留异常状态、展示原因并阻止重复启动。
- 软件异常退出后，下次启动核查遗留运行状态；确认已结束的旧记录标为中断，可能仍存活的受管进程须确认、清理后再允许启动同一任务。
- 不接管软件之外手动启动的相同命令。

## 第四轮：已确认与待澄清

用户接受 Q24 至 Q28 的推荐，拒绝 Q23 的固定 `cmd.exe` 建议，要求由用户手动填写执行命令。

- 完整命令、程序及文本组成项、工作目录、任务环境变量的值支持输入变量；文件引用不参与变量识别。
- `$${env}` 表示字面量 `${env}`；变量替换仅进行一次，不递归解释变量值中的占位符。
- 新发现的变量初始未赋值；允许空值的变量可使用空字符串。
- 数据根目录固定为用户主目录下的 `.script-hub/`，配置为 `config.json`，备份为 `config.backup.json`；导入文件、任务工作目录和日志分别在 `files/`、`workspaces/`、`logs/`。
- 界面提供打开配置目录的按钮。运行状态与历史独立保存，不持续写入用户编辑的配置文件。
- 全部任务停止后才允许重新加载配置，重新加载不触发任务自动启动。
- 保存前检查外部修改；发现冲突时停止写回，由用户选择加载磁盘版本或以软件中的版本覆盖，覆盖前备份磁盘版本。
- 重新加载校验失败时保留当前有效配置，展示具体错误。
- 每个导入文件使用独立目录并保留原文件名，界面支持打开所在目录。不分析、复制或安装依赖，用户自行准备依赖及项目环境，可设置工作目录指向现有项目。
- 替换文件时保留原有存储路径。
- 主界面包含任务列表、任务编辑区、运行输出区；另设文件管理和应用设置入口。
- 任务名称必填，支持新增、编辑、复制、删除、搜索，以及启动、停止和重启。
- 首版不增加任务分组、标签、拖拽编排或批量执行。
- 不采用统一固定 `cmd.exe` 的建议。用户手动填写执行命令；具体执行边界在第五轮澄清。

## 第五轮：完整命令执行语义已澄清

用户明确拒绝 Q29 中将最终命令解析成“程序＋参数”执行的建议，要求最终成为一条完整命令执行。

- 直接填写与组合编辑两种方式最终均生成一条完整命令字符串，并以完整命令语义执行。
- 组合模式的程序、文件引用、文本仅用于编辑；生成最终命令后，不再由应用解析成程序与参数数组分别调用。
- 保留已确认的顺序空格拼接、文件路径引号处理、变量单次字面替换和最终命令预览。
- 不要求用户额外选择执行终端，不把固定 `cmd.exe` 写成首版产品要求。
- 底层执行机制属于后续实现选择，必须符合完整命令语义，不改变用户已确认的命令输入模型。
